STATUSORBIT 使用指南

五分钟，熟悉你的系统工作台。

先理解状态，再查看证据，最后才执行操作。这份指南会带你认识每一个核心页面，以及哪些动作需要格外谨慎。

适用于当前 main 分支约 8 分钟阅读
01

快速开始

StatusOrbit 仍处于积极开发阶段，目前从源码构建。macOS 已完成真实窗口和原生构建验证；Linux 与 Windows 仍需要更多目标系统运行验证。

准备环境Node.js 22、pnpm 10.33、Rust 1.95，以及当前平台所需的 Tauri 2 系统依赖。
git clone git@github.com:JimmyDaddy/StatusOrbit.git
cd StatusOrbit
corepack enable
pnpm install
pnpm dev

构建原生应用时执行：

pnpm tauri build

第一次打开

  1. 1
    等待首轮采样

    网络和磁盘速率需要比较前后两帧，短暂显示“预热”属于正常现象。

  2. 2
    从简单模式开始

    它优先显示电脑是否正常、可能原因和建议，适合日常使用。

  3. 3
    按需切换专业模式

    需要 PID、协议、命令行和完整趋势时再展开技术数据。

02

概览与智能诊断

概览页把 CPU、内存、交换空间、磁盘和网络状态放在同一个视图中。智能诊断会等待持续证据，不会把一次瞬时峰值直接描述成故障。

◎先读结论

正常、观察、建议关注等状态比单独数字更重要。

⌁再看趋势

五分钟曲线可以区分短暂尖峰和持续压力。

↗打开证据

诊断会带你到相关页面，但不会自动处置。

03

应用与进程

简单模式把同一应用的辅助进程归在一起，适合回答“哪个应用正在占用资源”。专业模式提供平铺、进程树、搜索、排序和详细 Inspector。

  • 单击应用或进程查看路径、命令、父进程和五分钟资源趋势。
  • 优先使用“请求结束”，让应用有机会保存状态；只在必要时强制结束。
  • PID 会被复用，因此 StatusOrbit 还会核对进程启动身份；确认过期或身份不一致时会拒绝执行。
04

存储与安全清理

存储页用于判断磁盘是否紧张以及谁在读写；清理页用于回答空间去了哪里。扫描完整遍历选定范围，不会因为时间或数量限制静默停止。

点击进入目录拖到清理篮收集确认后永久删除
  1. 1
    扫描

    观察当前路径、已检查项目、已发现空间和耗时；需要时可以停止。

  2. 2
    浏览

    扇区面积按实际占用计算。点击进入目录，点击中心回到上一级。

  3. 3
    收集

    按住文件或目录扇区，拖入左下角清理篮。此时不会删除。

  4. 4
    复核并删除

    再次检查名称、路径、大小和变化，理解不可恢复提示后再确认。

永久删除不会进入废纸篓建议从可重新生成的缓存开始。下载、配置、工程文件和个人资料必须确认来源后再处理。
05

网络与启动项

活动连接

网络页展示上下行速率、启动后累计流量、接口信息以及 TCP / UDP 连接。进程归属取决于系统权限；没有进程名并不代表连接异常。

启动项

StatusOrbit 会展示常见用户级启动来源。可恢复的第三方项目能够停用和恢复；系统项目和平台暂不支持的来源保持只读。修改动作会复核文件身份，不会删除原文件。

06

历史、提醒与设置

  • 历史以五分钟快照保存 CPU、内存、磁盘和网络聚合趋势，并记录持续告警和恢复事件。
  • 保留期可选 1、7 或 30 天，也可以停用写入或清空全部历史。
  • 桌面提醒使用持续判定、恢复回差、冷却和每日预算，CPU、内存、磁盘可以分别关闭。
  • 设置还可以调整语言、系统采样间隔、连接刷新间隔、告警颜色和默认进程视图。
07

安全与隐私边界

进程操作短期单次租约、启动身份复核、关键 PID 和应用自身保护。
永久删除仅限主目录内普通内容；拒绝根目录、链接、特殊文件和跨挂载边界。
权限应用不会为了获得更多数据而自动提权，权限不足时明确降级。
隐私默认不上传遥测、进程、文件、历史或连接信息。
08

常见问题

刚启动时为什么没有网络或磁盘速率？

速率需要比较两次累计计数。等待下一个采样周期后会出现数据。

清理扫描为什么需要较长时间？

扫描不会静默截断。大量开发缓存、小文件和权限受限目录都会增加耗时，可以观察实时进度或主动停止。

为什么空间大小和 Finder / Explorer 不同？

StatusOrbit 优先显示实际磁盘占用。稀疏文件、硬链接、压缩和文件系统行为可能让它与逻辑大小不同。

开发时提示端口 1420 被占用怎么办？

通常是旧的 Vite/Tauri 开发进程仍在运行。结束旧进程后再启动，避免同时运行多个 pnpm dev 实例。

仍然需要帮助？

提交问题时请附上操作系统、复现步骤和相关错误信息。安全问题请使用私密漏洞报告。
