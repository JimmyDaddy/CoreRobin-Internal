# StatusOrbit 普通用户体验设计与实施路线

## 产品目标

StatusOrbit 不应该要求用户先理解 CPU、交换空间或进程树。普通用户打开应用时，首先需要知道三件事：

1. 电脑现在是否正常。
2. 如果变慢，最可能是什么原因、哪个应用影响最大。
3. 下一步能做什么，以及这个操作是否安全。

默认体验应当使用人话给出结论和证据；现有实时指标、进程树、连接列表等专业能力继续保留，作为深入查看的依据。

## 设计原则

- **先结论，后指标**：先展示“正常 / 正在观察 / 建议关注 / 影响明显”，再允许展开技术证据。
- **持续问题才报警**：短暂尖峰不是故障。需要趋势支撑的判断必须满足持续时间要求。
- **诊断不等于处置**：诊断中心只负责解释和导航。结束进程仍进入现有身份复核、租约和确认流程；永久删除必须逐项预览、复核状态并明确确认不可恢复。
- **不夸大确定性**：高网络流量不等于恶意软件，高内存占用不一定是内存不足，温度高也不一定存在硬件故障。
- **保护系统组件**：系统或受保护进程可以展示证据，但明确提示不建议直接结束。
- **数据留在本机**：诊断基于本机实时和聚合历史；默认不上传进程、文件或连接信息。

## 智能诊断 v1

首页新增“智能诊断”卡片。默认只显示一句状态结论；展开后展示五项检查、发现的问题、应用归因、原始证据和安全跳转。

### 诊断规则

| 检查项 | v1 判断 | 重要边界 |
| --- | --- | --- |
| CPU | 整机 CPU 连续至少 10 秒达到 75%；90% 以上为明显影响 | 短暂编译、启动应用或网页加载不提示 |
| 内存 | 可用内存低、交换空间已有实际使用，并且高占用持续至少 10 秒；极低可用内存与大量交换可立即提示 | 不能只因“已用 90%”提示，系统缓存会合理使用空闲内存 |
| 剩余空间 | 主要卷使用达到 85%，或剩余不超过 10 GiB；95% 或不超过 2 GiB 为明显影响 | 忽略小于 4 GiB 的伪文件系统与系统挂载点 |
| 磁盘 I/O | 读写合计连续至少 10 秒达到 50 MiB/s；200 MiB/s 以上为明显影响 | 速率只表示磁盘繁忙，不宣称磁盘损坏 |
| 网络 | 收发合计连续至少 10 秒达到 25 MiB/s，或活动连接达到 500；更高阈值升级提示 | 只描述流量或连接规模异常，不判断远端是否恶意 |

阈值是用于 v1 降低误报的保守起点，后续应根据真实设备数据和用户反馈校准，不应直接复用为硬件健康评分。

### 应用归因

- 将 `Code Helper`、`Code Helper (Renderer)` 等辅助进程合并到 `Code`，CPU、内存和磁盘活动按应用累计。
- 归因结果保留一个代表进程，用户点击后进入现有 Process Inspector 核对证据。
- 受保护进程或 root / system 等系统账户下的组件标记为系统组件。
- v1 不把连接强行归属给应用；跨平台进程归属不完整时保持“未知”，不猜测。

### 状态模型

- **正在观察**：尚未形成 10 秒稳定基线，但空间不足等即时问题仍可出现。
- **运行正常**：稳定基线内未发现五类明显问题。这不是永久健康保证。
- **建议关注**：发现可能影响体验的持续问题。
- **影响明显**：指标达到更高阈值，建议尽快核对证据。

StatusOrbit 不使用缺少依据的综合健康分数，避免“82 分”这类看似精确、实际不可解释的结论。

## 完整能力路线

### P0：已经进入实现

1. **一键解释变慢原因**：完成五类纯函数诊断、持续判定、应用聚合、双语界面与安全跳转。
2. **清晰的电脑状态**：首页状态卡片覆盖正在观察、正常、关注和明显影响，不制造虚假精度。
3. **应用级归因基础**：辅助进程合并为应用，并保留进程级 Inspector 作为证据。
4. **空间清理助手**：独立页面、完整后台扫描、主动取消、实时进度、隐藏目录分类、可就地操作的扇形空间图、7 天结果保留、当前目录变化提醒和长期未使用应用的只读盘点已经落地；文件只会在清理篮复核、一次性租约确认和状态复查后永久删除。

### P1：安全且高频的下一步

5. **安全建议操作**
   - 给应用区分“普通应用 / 系统组件 / StatusOrbit 自身”。
   - 优先提供“查看详情”“请求正常退出”；强制结束继续放在二次确认后。
   - 每个操作在执行前说明影响，执行后验证结果并允许用户回看。
   - **当前状态：已实现。** 应用与系统组件分层展示，进程操作继续使用身份复核、租约、确认与结果反馈。

6. **简洁模式与专业模式**
   - 简洁模式默认展示状态、原因、应用和建议，隐藏 PID、句柄、协议细节。
   - 专业模式保留当前仪表盘、进程树、连接表和全部技术字段。
   - 两种模式共享同一份采样与安全逻辑，切换不丢失选择和历史。
   - **当前状态：已实现。** 简洁模式优先给出状态、原因和建议，专业模式保留进程、存储与网络技术视图。

### P2：需要新增系统数据源

7. **清理助手的安全删除阶段**
   - 已完成下载、废纸篓、常见缓存、用户隐藏目录与大文件的只读完整扫描，不以时间或项目数量静默截断。
   - 已支持实时进度、取消、权限缺失说明、可下钻扇形图和只读清理预览。
   - 文件按“可安全清理 / 需要确认 / 不建议触碰”分级，并解释来源和最近使用时间。
   - 永久删除前逐项预览，明确提示不可恢复并要求再次确认；清理结果可核对。
   - **当前状态：已实现。** 扇区拖入清理篮后才进入复核；路径、符号链接、父子重叠、扫描后变化与一次性确认都会再次校验。

8. **启动项管理**
   - 展示登录项、常见自启动位置、发布者、影响和当前启用状态。
   - 默认只建议禁用第三方非必要项，不把系统守护进程包装成普通开关。
   - macOS、Windows、Linux 分别实现能力探测；权限不足时只读展示。
   - **当前状态：已实现首版。** 可恢复的用户级第三方项目允许停用/恢复，系统或平台不支持的来源保持只读。

9. **温度、风扇和耗电解释**
   - 采集平台可用的温度、热压力、电源状态与应用能耗指标。
   - 使用“正在升温，可能因为视频导出”一类因果谨慎的描述，不根据单点温度宣称硬件故障。
   - 无可靠传感器时隐藏模块，不用估算值冒充实测值。
   - **当前状态：已实现首版。** 展示平台可用的温度、电池与阻止睡眠信息；缺失传感器明确显示不可用，不伪造估算值。

### P3：持续陪伴但不打扰

10. **克制的桌面通知**
   - 仅对持续且可行动的问题通知，例如磁盘即将满、某应用长期异常占用。
   - 同类问题设置恢复回差、冷却时间和每日上限；默认不通知短暂 CPU 峰值。
   - 通知直接打开对应证据，并可按类别永久静音。
   - **当前状态：已实现首版。** 使用持续判定、恢复回差、冷却与每天最多 4 条通知；CPU、内存和磁盘可分别静音，点击通知进入对应证据页面。

11. **人话历史故事**
    - 将本机聚合历史总结为“下午 2 点附近持续繁忙 8 分钟，主要是磁盘写入”。
    - 明确区分采样事实与推测原因；只有有进程证据时才点名应用。
   - 默认保留当前隐私边界，不持久化命令行、路径、连接地址或进程名称；若未来增加应用故事，需要单独征得用户同意。
   - **当前状态：已实现首版。** 告警与恢复会合并为包含开始、峰值、结束和持续时间的故事；应用显示名只有在设置中单独允许后才会持久化。

## 数据与平台前置条件

| 能力 | 需要补充的数据或系统接口 |
| --- | --- |
| 应用图标与可靠聚合 | 可执行文件 / bundle 身份、签名与图标缓存；跨平台应用 ID 规范化 |
| 网络应用归因 | 各平台连接到稳定进程身份的映射，以及权限降级策略 |
| 清理助手安全删除 | 已接入永久删除、路径与挂载边界保护、状态复核、不可恢复确认及结果反馈 |
| 温度与耗电 | macOS thermal state / 能耗、Windows 电源与传感器、Linux hwmon 等能力探测 |
| 启动项 | LaunchAgents / 登录项、Windows Startup 与 Run keys、Linux autostart 的只读与变更接口 |
| 桌面通知 | 已接入 Tauri notification 权限、去重、冷却、每日预算、点击路由和分类静音 |
| 人话历史 | 已接入事件聚合、恢复事件、峰值时间、应用证据和独立隐私选项 |

## 验收方式

- 使用纯函数和固定时间序列覆盖边界值、短暂尖峰、持续问题、数据缺失与乱序样本。
- 中英文键保持完全一致，核心状态不能回退到开发者术语。
- 在 1280、1080、940 像素宽度验证默认和展开状态，不遮挡 Inspector 或主要操作。
- 真实桌面窗口验证暂停 / 继续、低频连接扫描和从诊断到 Inspector / Storage / Network 的联动。
- 所有会改变系统状态的能力必须有平台能力探测、明确预览、确认和结果复核。
