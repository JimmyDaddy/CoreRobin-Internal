# AI 方案与实现消融试验

> 本文记录工具增量之前的消融结果。随后按用户要求加入的固定工具执行能力见 [任务执行增量](../ai-task-execution-design.md)，不改变普通聊天一步发送和自然语言回答。


日期：2026-09-08。范围：AI 接入设计及全部 AI 实现、共享 IPC/窗口/隐私清除接点。仅 Internal；不改公开仓库，不提交、不发布。

## 方法与基线

按“移除一个机制 → 检查仍需保留的用户行为 → 运行对应验证 → 决定保留或删除”执行。统计基线为一步发送修复后、进一步消融前的 53 个方案与源码文件，位于忽略目录 `.local-dev/ai-ablation/baseline/`，包含逐文件 SHA-256、字节数与行数，不包含用户数据或凭据。测试日志保留在 `.local-dev/ai-validation/`。

一步发送基线：助手 42 条测试通过，6 个主窗/气泡浏览器 smoke 通过；新增连接版本冲突原生回归通过。此前全量原生为 476 条通过、5 条显式忽略；新增连接版本回归后基线应执行 477 条，最终消融后的全量结果见下表。浏览器 fixture 与真实原生验证分开记录。

## 方案消融结论

| 机制 | 移除后失去什么 | 决定及理由 |
| --- | --- | --- |
| 普通发送二次确认、记住/撤销授权、授权指纹 | 仅失去重复的聊天审批交互 | 删除；按发送已表达本轮发送意图，路由和上下文仍清楚可见 |
| 自由文本敏感词/路径启发式告警 | 不再对用户明确输入的文字重复提醒 | 删除；没有完整脱敏能力，也不约束自动上下文；可选查看原文足够 |
| consentEpoch 与 dataEpoch | 失去两种名称区分 | 合并为 requestEpoch；每次 dataEpoch 递增原本都会同时失效 consentEpoch，没有独立消费方 |
| 应用每日请求额度与计数表 | 不再自行在第 N 次阻断用户自己的服务 | 删除；保留实际服务限流、超时、单并发和大小预算 |
| 场景模型覆盖表 | 不再为三个数据场景分别维护默认接收方 | 删除；统一新会话默认模型，既有会话选择不变 |
| 服务层窗口字符串身份检查 | 不再把 UI 身份传遍领域方法 | 删除重复层；Tauri capability 保留为唯一窗口权限入口 |
| 自动 Schema 格式与测试驱动聊天行为 | 普通消息不再自动被包装成诊断 JSON | 删除；实机普通问候复现了错误耦合，已有结果只读展示保留 |
| 能力记录重复协议/流式/输出字段 | 不再重复保存同一配置的副本 | 精简；连接 ID + revision 已覆盖这些设置，模型与测试类型仍独立 |
| 冻结请求、会话版本、草稿版本和提交 ID | 会导致过期内容、跨窗覆盖或重复生成 | 保留，并以反向消融验证实际失败 |
| 来源清除 gate、恢复标记与请求失效 | 旧上下文和迟到写入可能复活 | 保留；这是数据一致性，非聊天审批 |
| 四协议适配、网络限制、系统凭据库 | 失去真实兼容性或泄露凭据 | 保留；不为减少文件数混合职责 |
| SQLite、临时会话与历史分页 | 失去持久恢复或明确选择的不留记录 | 保留；一个存储权威，不增添通用存储接口 |
| 独立气泡、共享 hook、删除确认组件 | 丢失可用输入空间、跨窗状态或删除保护 | 保留；对应当前用户功能和实际复用 |
| 未来工具 registry、审批引擎、通用 agent 框架 | 当前功能没有损失 | 从本期方案移除；代码中不新建这些抽象 |

## 代码执行与结果

| --- | --- | --- |
| 直接发送与可选查看 | `AiAssistant` 的 Enter/发送直接准备并启动，设备上下文默认仍勾选；查看入口不发送 | 主窗/气泡 Enter、连续 Enter 去重、关闭数据选项、原文查看/取消和失败保留草稿测试；6 个浏览器 smoke |

| 合并失效代次 | `consentEpoch` / `dataEpoch` 合为 `requestEpoch`，准备、运行、模型测试和目录发现共用 | 配置失效、删除、迟到输出、来源清除与退出回归；未动会话和草稿独立版本 |
| 删除每日额度 | 移除设置字段、输入框、计数读写、启动时额度拒绝和测试请求计数；旧 `ai_daily` 及 grants 元数据在打开数据库时退役 | 旧数据迁移回归包括超出原额度的记录、无效旧 grants、指向已删除连接的旧场景覆盖；连接、会话选择及中文/自由文本草稿保存机制不变 |
| 统一默认模型 | 删除场景覆盖表和三个设置分支；场景仅决定上下文 | 三个场景新建会话均采用同一默认模型；既有会话不改接收方；只允许本机连接的用户设置仍生效 |
| 单一窗口权限入口 | 22 个原生服务方法不再接收窗口身份字符串；删除两套重复 label 检查，移除命令层仅为鉴权传递的 WebviewWindow 参数 | 5 条 surface contract；遍历全部 capability 文件，配置/凭据/来源清除仅 main，聊天仅 main/robin-chat，无远程或通配窗口授权；完整 Tauri 构建验证注册表 |
| 精简能力记录 | 删除与连接 revision 重复的 protocol/stream/maxOutputTokens 字段；记录不再影响生成格式 | UI 仍按连接 revision 和模型过滤，旧 Schema 记录忽略，地址/目录/文本记录仍可查看 |
| 删除强制结构化对话 | 移除 Schema 生成参数、格式提示、测试按钮及其状态分支；保留已有结果卡的安全解析/展示 | 四协议普通请求均无格式参数；重开带旧 Schema 记录的数据库仍使用自然语言系统提示 |
| 移除虚假错误返回 | `stop_active` / `invalidate` 不再返回永远为 Ok 的 Result，调用方删除无效 `?` | 存储失败仍由持久化 helper 写入可见状态，既有失败/取消测试继续覆盖 |

## 保留项反向试验

在离线原生测试中逐项短暂移除以下保护，执行一个明确的行为测试，再逐字节恢复文件。每次都因行为断言失败而退出 101，不是编译失败；恢复前后 SHA-256 相等。弱化版本没有打包或启动。日志与恢复哈希位于 `.local-dev/ai-ablation/negative-controls/`。

| 移除的保护 | 观察到的失败 | 最终决定 |
| --- | --- | --- |
| 草稿版本 CAS | 旧版本保存被接受，另一窗口可以覆盖较新的草稿；原冲突测试得到错误的成功结果 | 保留 |
| 已清除来源的会话隔离 | 旧助手消息仍 `reusable_in_context=true`，后续上下文可能重复发送已清除内容 | 保留 |
| submissionId 去重回执 | 同一提交不再返回原 requestId，第二个视图误报 `busy`；不能仅以单并发替代提交回执 | 保留 |
| 网络地址分类 | 禁止的 `0.0.0.0` 公网目标被接受；该试验只调用纯地址校验函数，没有访问禁止地址 | 保留 |

试验完成后重新执行全量原生测试及 Clippy，通过后才构建最终应用。这里没有声称每个保留组件都做了动态变异；其他组件的判断来自实际职责、已有故障回归和本次全量验证。

## 净变化与验证范围

相对上述一步发送后基线，方案正文从 **508 行减至 124 行**；16 个相关实现文件合计净减少 **846 行 / 28,856 字节**。实现口径包含 Rust 文件中的内联测试，排除文档、翻译、生成类型和独立测试文件；它衡量维护体积，不代表相同幅度的性能收益。另移除十语言中每种语言 15 个废弃键，并重新生成翻译类型。

生产全量 JS 从 **3,826,459 降至 3,812,731 字节**（减少 13,728）；CSS 从 **491,981 降至 491,578 字节**。最终原生构建前重新生成前端资源并检查包体，主窗和辅助入口均通过原有门槛，本次没有放宽预算。没有进行受控延迟、能耗或内存基准，不把模型响应耗时当作消融收益。

### 已授权服务回归

沿用用户已授权的 DeepSeek 环境变量和运行中的 Ollama，全部使用固定合成文字、临时进程内凭据及独立自动清理的 SQLite。自动化 smoke 没有发送设备数据、读取真实会话、下载模型或修改/停止用户服务。原生 UI 另用临时会话、保留默认设备聚合摘要向用户允许的本机 Ollama 验证；不向云端发送设备数据。

- DeepSeek `deepseek-v4-flash`：Chat 文本、目录、持久会话/去重/重开/删除通过。Schema 参数仍被服务拒绝，记录失败后普通文本成功。
- DeepSeek Responses/Messages：初次 Responses 在 DNS 阶段失败；之后目录/Chat 已成功，单独确认 DNS 恢复后人工重跑该合成测试，四种流式/非流式组合全部通过。应用未增加自动重试。
- Ollama `llama3.2:latest`：目录、文本、Schema 自测和持久会话回归通过。本轮普通回答未形成有效结构化卡，按文字保存；不能把一次 Schema 自测成功解释成每次回答都遵守结构。既有离线结构化校验/失效测试继续通过。

上述为首轮删减后的结果。随后原生界面用一句问候复现了 Schema 状态把普通聊天强制成 JSON，促使进一步删除整段耦合。该临时会话已删除，原有“你好”草稿及历史保留，原草稿未发送。

最终自然语言版本另外执行两项原生服务 smoke，结果为 **1 通过、1 失败**，日志见 `.local-dev/ai-validation/ablation-live-text-final.log`：

- Ollama：目录、流式文本、持久会话、重开及删除通过；文本耗时 1,935 ms，会话耗时 566 ms，收到真实流式事件，回复按普通文字保存。
- DeepSeek：目录成功返回 3 个模型；流式文本在测试配置的 10 秒时限内未完成，10,050 ms 返回 `timeout`，该项后续会话步骤未执行。不修改超时以获得绿灯、不自动或反复重试付费请求，也不以首轮成功覆盖本轮失败。

用户手动解锁后，正常退出并重开最终 `CoreRobin AI Test.app`，确认用户刚新增的三轮对话完整恢复、输入框为空；不恢复过时的“你好”草稿，也不代发原有内容。新建临时会话，发送固定问候，默认设备上下文保持勾选；Enter 后立即出现发送中状态，没有二次确认，随后本机 Ollama 返回普通文字“你好。”（输入 747 / 输出 4 Token）。已目视核对输入区、上下文选项和回答展示，并仅删除本次临时会话，切回用户最新会话、收起历史栏，保持测试版运行。该补验没有修改产品代码或重跑云端请求，记录见 `.local-dev/ai-validation/ablation-final-native-ui.json`。

三个首轮真实服务 smoke 最终分别通过；保留首次 DNS 失败日志，不把重新执行写成首轮全绿。最终 DeepSeek 超时仍未消除；锁屏导致的最终界面补验缺口已补齐，但此次解锁不等同于完整锁屏行为验收。当前回归不等同于其他服务账号、Ollama 冷启动、三平台原生输入法/锁屏或长期性能验收。
