# 国际化维护指南

StatusOrbit 使用 `i18next`、`react-i18next` 和 `i18next-cli`。语言、目录、加载策略和类型检查已经拆开，新增语言不需要再修改主界面、托盘或通知组件。

## 已支持语言

- `zh-CN`：简体中文
- `en`：English
- `zh-Hant`：繁體中文（`zh-TW`、`zh-HK`、`zh-MO` 等系统 locale 会按繁体脚本匹配）
- `ja`：日本語
- `de`：Deutsch
- `fr`：Français
- `es`：Español
- `pt-BR`：Português (Brasil)
- `ko`：한국어
- `ru`：Русский

系统 locale 会先按完整 BCP 47 标签和显式别名匹配，再按文字脚本和基础语言匹配。例如 `zh-Hans-HK` 使用 `zh-CN`，`zh-Hant-SG` 使用 `zh-Hant`；当前仅提供巴西葡萄牙语时，其他 `pt-*` 变体也会使用 `pt-BR`。没有匹配项时回退到 `zh-CN`。

## 目录结构

翻译资源位于 `src/i18n/locales/<locale>/<namespace>.json`。当前 namespace 定义在 `src/i18n/namespaces.ts`：

- 主窗口按当前语言动态加载业务 namespace；
- 启动画面、托盘和 Orbit 小伙伴只加载它们需要的 namespace；
- 桌面通知在发送时单独加载 `notifications`，不会进入主窗口首屏资源。

代码中的 key 使用 `namespace:path.to.key` 形式，例如：

```ts
t("settings:language.title")
```

## 新增一种语言

1. 在 `src/language.ts` 的 `SUPPORTED_LOCALES` 中增加 BCP 47 locale、原生名称、紧凑标签和文字方向。
2. 复制一个现有语言目录为 `src/i18n/locales/<new-locale>`，保留全部 namespace 和 key，再完成翻译。
3. 运行 `pnpm i18n:status` 检查目录完整度和缺失翻译。
4. 运行 `pnpm i18n:types` 更新自动生成的 `src/types/i18next*.d.ts`。
5. 运行 `pnpm i18n:check` 和项目常规质量检查。

语言选择器直接读取 `SUPPORTED_LOCALES`，因此新增语言后主窗口和设置页会自动出现新选项。`normalizeLanguage` 会把浏览器或系统提供的地区和脚本变体匹配到已支持的 locale，并在没有匹配项时回退到 `zh-CN`。

## 修改翻译

- 新增静态 key 后运行 `pnpm i18n:extract`，再补齐各语言翻译。
- 动态 key 应优先写成有限的常量映射或可推导的联合类型，避免任意字符串绕过类型和目录检查。
- 各语言的 key 和 `{{variable}}` 插值契约必须一致；允许按 CLDR 增加 `_few`、`_many` 等目标语言专属复数 key，`src/i18n.test.ts` 会逐 namespace 校验。
- 新增或大批修改翻译时，除了自动检查，还应由对应语言的母语使用者复核删除、权限、进程终止、错误通知等高风险文案。
- `src/types/i18next.d.ts` 和 `src/types/i18next-resources.d.ts` 由 CLI 生成，不要手工编辑。

## 常用命令

```bash
pnpm i18n:status   # 检查已使用 key、缺失翻译和语言完成度
pnpm i18n:extract  # 从源码提取新增 key
pnpm i18n:types    # 重新生成 key 和插值参数类型
pnpm i18n:check    # 运行状态、类型时效和核心 i18n 测试
```
