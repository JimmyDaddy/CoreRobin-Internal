# 应用能力、对话卡片与共享结果

状态：2026-09-08，55 项能力接入、自动化验证与 macOS 原生抽样验收完成；平台与副作用覆盖边界见文末。

## 要解决的问题

AI 已能调用原生检查，但结果只显示 JSON；用户无法像在功能页面一样查看和操作。扫描虽然写入现有索引，已经挂载的页面不会及时接收更新。把完整页面复制进对话、或者只加一个跳转按钮，都不能解决能力重复和数据分叉。

## 约定

1. **能力只有一份执行逻辑。** 原生采样器、扫描任务管理器、扫描索引、网络检查器和进程／清理控制器继续拥有实际能力；AI 工具和用户点击是两种入口。
2. **业务结果与模型摘要分离。** `CleanupScan`、`NetworkQualityResult` 等现有类型是功能页可直接使用的结果；给模型的脱敏、限长摘要只是一种投影，不能替代或覆盖业务结果。
3. **页面与卡片共用操作组件。** 提取进程操作按钮、文件项目摘要／选择、风险确认等可嵌入组件；大页面保留导航和复杂布局，对话提供紧凑布局。卡片不是模型生成的 HTML 或任意 UI 指令。
4. **结果变更可订阅，也可重新读取。** 原生发布只含能力和版本的变更通知；功能页和卡片重读同一份原生结果。事件丢失、窗口重新打开时仍可恢复。新扫描、目录刷新、清理和数据清除均属于变更，不能只通知 AI 发起的路径。
5. **历史与当前状态有区别。** 对话保存当时的只读快照。卡片显示当前结果是否已更新或失效；不得把另一份扫描伪装成旧消息的结果，也不得让旧目标继续可执行。
6. **点击操作不依赖模型。** 用户点击卡片直接走固定能力分发与现有任务生命周期，不再让模型猜测目标或要求用户再输入一句话。原生按会话、步骤、目标引用和当前数据验证请求，不接受模型提供的任意路径或 PID。
7. **确认与权限不降级。** 检查可直接发起；关闭／强制结束进程、移到废纸篓仍需展示原生目标和风险并显式确认。复用现有控制器的身份校验、租约、过期、单次执行和取消。对话不增加永久删除、任意命令执行、自动提权或文件内容读取。

## 首批能力

| 能力 | 业务数据源 | 对话表现与操作 | 页面一致性 |
| --- | --- | --- | --- |
| 设备状态 | 原生 sampler | CPU、内存、磁盘、温度摘要；刷新 | 与设备页面同源 |
| 进程占用 | 原生 sampler + ProcessController | 进程列表、占用、关闭／强制结束确认；刷新 | 相同身份与控制器；执行后刷新采样 |
| 网络检查 | 原生 NetworkQualityResult | 分项结果、失败原因、重新检查 | 最新检查与网络页面共享；记录开关不被改变 |
| 磁盘扫描 | CleanupScanJobManager + 现有 SQLite 索引 | 可读大小、数量、风险、选择与移到废纸篓确认；重新扫描 | AI／页面任一入口完成后，另一入口立即看到相同 scanId 和版本 |
| 已记录历史 | 现有本地历史存储 | 覆盖范围、记录摘要、刷新 | 不创建假记录，不自动开启记录 |

其他页面和工具箱能力已按[逐项接入清单](application-capability-inventory.md)完成本阶段接入；敏感操作保留用户输入和确认。原有模型协议的 `CapabilityRecord` 表示服务兼容性，与这里的应用能力目录不是同一概念。

## 验收

- 磁盘结果默认无需展开 JSON 即可阅读；可在对话内选择真实项目并请求清理，确认前不移动文件。
- 页面已挂载时，AI 扫描完成仍自动更新；页面刷新／清理后，旧卡片不会继续以旧目标执行。
- 卡片操作无需调用模型；保留未发送草稿；双击、过期、重启、删除会话、清除源数据不能绕过目标校验。
- 共享组件在页面和 400×540 Robin 小窗均可用；原有页面操作不退化。
- 测试覆盖业务数据一致性、丢失通知恢复、清除与在途请求竞争、拒绝／取消／重复确认、跨会话伪造目标和真实本机只读验证。真实用户文件和进程不作为破坏性测试对象。

## 已接入的操作层与执行边界

- `ApplicationCapabilityProvider` 只持有 App 已有控制器的视图绑定。`BusinessOperations` 按需装配共用操作组件，覆盖清单中 19 项业务功能；文件整理、启动项、应用管理、历史和隐私控制不产生第二份 AI 专用数据源。
- `ToolOperation` 从工具箱目录页拆出，同一个实现覆盖 36 项工具。图片／补丁／文件哈希仍沿用既有 session/job/output token；文件和密钥由用户在本机提供，模型只能打开表单。Wi-Fi 密码及其二维码不保留到共用状态。
- `QuickCleanCoordinator` 统一分析、清理、取消与当前结果。AI 可执行分析；删除操作由用户选类别后确认，界面说明永久删除风险。清空数据会取消工作并拒绝晚到结果，直到工作线程真正退出才释放并发槽。
- `run_local_utility` 是有限文本计算协议：8 类工具、15 种操作，输入上限 4096 UTF-8 字节，JSON／编码／时间／UUID／SHA-256／正则／颜色复用现有固定函数，不接受脚本或文件路径指令。原生一次性请求由主窗口领取和回执；取消、重复、过期、清空及用户后续编辑不能恢复或覆盖旧结果。回执给出有界结果片段，完整结果进入对应工具的内存状态；从不读取用户已有输入发送模型。
- 气泡仍只具备原有狭窄权限；文件选择和业务管理操作通过保留会话位置的主窗口继续入口展开。三条计算桥接 IPC 仅授予 main，均再次检查窗口身份。

## 体积控制记录

业务装配器和结果卡片均按需加载，保留主窗口及各辅助窗口原有首屏预算。2026-09-08 构建显示，新增能力目录、共用操作视图、计算桥接与十语言卡片文案后，全量非 C2PA JavaScript 为 3,954,208 字节；此前任务执行构建为 3,833,009 字节，增加约 3.16%。总 JavaScript 预算据此调整到 3,960,000 字节；CSS 总预算与各入口预算不变。此处记录的是全部按需资源体积，不将它视为启动时全部加载。

## 当前验证进度

55 项表单的浏览器打开验证以及卡片 JSON 结果在原工具箱继续使用的验证通过。原生全套当前 508 项通过、7 项环境相关测试跳过；前端全套 839 项通过，类型、ESLint、Clippy 及十语言检查通过。最终检查修复了桥接权限名单、确认过期时钟、清除后的 GPU 请求归属、计算请求领取期间的新编辑保护，以及结果卡片延迟加载后小窗确认按钮超出可见范围的问题。新版独立测试应用的原生 UI 验证结果见接入清单。破坏性操作只用合成目标／测试目录验证，不操作用户真实文件与进程。

最终独立测试包已验证非空 JSON 的模型调用与原生计算回路、对话操作区和原工具箱共享结果、手动 JSON 编辑、设备卡片直接刷新与草稿保留；隐私操作区的嵌套清除确认可取消且未清除数据。所有测试临时会话已清理，原有五条会话与八条运行记录的内容哈希保持一致。小模型仍可能生成错误参数或误读数值，失败回执不被替换为模型文字成功。Windows/Linux 原生 UI 和全部系统副作用不在此次实机覆盖内，详见接入清单。
